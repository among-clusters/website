互联那些不归你管的集群。

Among Clusters 是主权集群互联控制面。每个 Kubernetes 集群都是独立的信任域。Hub 只分发签名身份、信任包与明确的服务公告，从不接收 Kubernetes 凭据，也不在数据路径上。

信任模型

每个集群保管自己的钥匙。

每个集群保留自己的 API Server、CA、RBAC、调度器与生命周期。互联只分发认证与路由一个明确公告的服务所必需的内容。

由 Hub 分发

  • 签名身份 · 由所有者侧 Agent 创建并保管
  • 信任包 · 双方确认摘要后才安装
  • Gateway 端点 · 用于 QUIC 与 TLS 1.3 双向认证
  • 服务公告 · 选定的 L4/L7 服务，绑定目标 Peer

从不同步

  • Kubernetes 凭据 · Hub 从不接收
  • PodCIDR 与 EndpointSlice · 没有 Pod 地址跨越边界
  • 远端 API 密钥 · 不分发 kubeconfig
  • 托管访问 · ManagedAccessGrant 独立受控，默认关闭

安装

接入自己的集群，保留本地权威。

在配置公网端点和已确认的 peer-bundle Secret 之前，Gateway 的 UDP 监听保持关闭。

  1. 安装 Hub，或加入已有的 Hub。
  2. 把签名的 Agent Chart 装到独立命名空间，镜像固定摘要。
  3. 给 Service 打上 peering.re8ch.com/advertise=true 和策略注解。
场景矩阵 →
export.sh
# 把一个 Service 公告给已批准的对端
kubectl label service orders peering.re8ch.com/advertise=true
kubectl annotate service orders \
  peering.re8ch.com/protocol=tcp \
  peering.re8ch.com/service-class=app.orders \
  peering.re8ch.com/policy-ref=orders-policy \
  peering.re8ch.com/target-peers=cluster-b \
  peering.re8ch.com/ttl-seconds=300

# 移除标签即撤销
kubectl label service orders peering.re8ch.com/advertise-
